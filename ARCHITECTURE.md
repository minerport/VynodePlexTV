# Afterglow TV — architecture

An independent, self-hosted television experience powered by Plex. This repository has no relationship to or dependency on VyNode Media. Phase 0 established the foundation; Phase 1 adds real Plex inventory services. No schedule or playback behavior is simulated.

## Repository

```text
cmd/server/                     process startup and graceful shutdown
internal/config/                environment configuration
internal/database/migrations/   embedded, ordered SQL migrations
internal/httpapi/               versioned routes, auth, middleware
internal/plex/                  Plex adapter, encrypted server service, inventory/jobs/cache/linking
internal/scheduler/             persisted deterministic scheduling domain, policies, jobs and queries
web/src/                       React TV shell and API client
web/e2e/                       browser functional tests
Dockerfile                     reproducible frontend/backend/runtime stages
compose.yaml                   persistent /config deployment
```

## Boundaries

The Go process owns authentication, authorization, configuration, SQLite and all business logic. React owns presentation, input/focus behavior, and explicit loading/empty/error states. It accesses only `/api/v1`; it never reads SQLite or receives saved Plex tokens. Manual credential entry is submitted once through a password field, while account linking returns only a short-lived Plex authorization URL and sanitized server choices. The production process serves the built SPA and API from one origin. Vite proxies `/api` in development. Native clients can use the same versioned JSON API; their authentication transport will be specified before implementation.

Phase 0 uses standard-library HTTP, modernc SQLite, bcrypt passwords, opaque cookie sessions and structured JSON logging. Session tokens are generated cryptographically; only SHA-256 token digests are stored. Sessions expire after 24 hours. Every authenticated mutation requires an exact configured Origin and a per-session CSRF token. Logout revokes the session. Setup creates the first OWNER transactionally and becomes unavailable afterward. Login attempts are rate limited. Public responses never contain password hashes or session tokens.

Roles are OWNER, ADMIN and USER. Only OWNER/ADMIN may change application settings. Account creation/management beyond first-owner setup is deferred. First-run setup is available to whoever can reach the service, so complete setup on a trusted host before exposing it to the LAN. TLS termination and secure cookies are required when exposed beyond a trusted LAN.

## Storage and migration strategy

SQLite lives at `/config/afterglow.db`, with WAL, foreign keys, a busy timeout, and a single connection for predictable transactional writes. Migrations are embedded numbered SQL files applied transactionally. A `schema_migrations` ledger stores version and checksum: edited applied migrations or a database newer than this binary fail startup. New schema changes require new migrations, never edits to deployed files. Back up the database using SQLite's backup facilities or stop the container before copying the entire config directory. Downgrades require a matching backup; no destructive automatic down migrations.

Migration 001 contains only users, user_preferences, sessions, app_settings and audit_log. Later migrations add plex_servers, plex_libraries, plex_media_items, plex_media_versions; channels, channel_sources, channel_rules, channel_groups; channel_schedules, schedule_blocks, program_entries; viewing_sessions, playback_history, favorites; interstitials and channel_interstitial_rules. Avoid empty speculative tables in the first migration. Domain IDs and Plex source IDs will remain distinct. Foundation timestamps are UTC Unix seconds; Phase 3 program timing uses UTC Unix milliseconds to preserve exact media durations. UI rendering uses an IANA timezone setting. Future block scheduling must explicitly resolve DST gaps and folds.

## Plex boundary (Phase 1)

`internal/plex.Provider` now expresses identity, complete library discovery, bounded pages, detailed normalized metadata and artwork. `Client` alone understands XML, Plex endpoints and headers. `Service` owns server/library persistence, inventory, jobs and cache. HTTP handlers call the service and enforce admin authorization; raw Plex XML and credentials never reach React. The future scheduler remains untouched and independent of these transport models.

Migration 002 adds server/library/media tables, unified metadata entities plus typed relationships, external IDs, normalized versions/parts/streams, jobs, observed-item markers, Plex settings and artwork cache metadata. Metadata entity identity is scoped to Plex server and kind plus a Plex ID when supplied. Missing IDs fall back to server/kind/name identity; this is not a claim that names are globally unique. People use one entity kind with actor/director/writer relationships. Hierarchy retains source parent/grandparent keys with composite indexes. Filesystem paths are internal only. Unsupported library types remain discoverable but cannot be selected.

AES-256-GCM ciphertext is bound to server ID and key version. The separate persistent key and client identifier are generated once in /config/secrets. Missing encryption material with existing credentials prevents startup. Account linking uses Plex's strong PIN flow; it is opt-in per administrator, holds secrets only in bounded memory, expires in at most ten minutes and validates a resource's machine identity before storing its server-specific token. Cloud account access is needed only during optional account linking; direct local operation and manual setup do not depend on a hosted Afterglow service.

One durable worker claims queued jobs and performs sequential, paginated I/O. A scan validates server identity, library UUID/type/revision, explicit totals, offsets and unique observations. Changed metadata is committed per page. Incremental scans still enumerate all identities, skipping detail requests only when source timestamps match. Final missing-item marking, library timestamps and SUCCEEDED status commit in the same transaction after checking cancellation. Failed/cancelled/interrupted work cannot reach that transaction. Restart cancels RUNNING jobs and clears their observation markers; queued work remains durable. Outages retain inventory, and reconnection restores health through scheduled checks or successful sync.

Artwork paths are restricted to relative Plex library paths. Redirects and unexpected content types are rejected. A serialized cache fill avoids duplicate downloads and eviction races; LRU eviction enforces a configurable byte budget. Authentication precedes even browser conditional-image responses. Cached images can survive temporary server failure without implying media availability.

Plex calls use normal TLS verification, five-second connection/TLS limits and twenty-second request limits with at most one short retry for transport/server errors. Authentication failures are not retried. Public errors are fixed safe messages; raw URL errors and upstream bodies are never logged. Frontend status polling is intentionally simpler than introducing SSE without a current need. Real Plex validation remains a distinct gate from deterministic HTTP fixtures.

The transport recognizes only canonical IPv4 plus 32-hex certificate identifier `plex.direct` names for a DNS-failure fallback to the embedded address. The original hostname remains authoritative for TLS SNI, certificate verification and HTTP Host. Other hosts, invalid addresses and non-DNS failures are not rewritten; no public DNS dependency or global resolver change is introduced.

## Scheduler boundary (future phases)

`internal/scheduler.Generator` accepts normalized content, a channel revision/seed, and a UTC horizon. It returns deterministic entries independent of Plex HTTP structures. A persistence service will transactionally append schedules, preserve already-generated unaffected entries, and enforce non-overlap/idempotence. Target retention is seven days past and fourteen days future. Clock injection makes lookup and join-in-progress offsets independently testable. Advanced blocks, timezone-aware slots and interstitial policy are separate later extensions; Phase 0 does not implement scheduling.

## Deployment and operations

A single non-root container serves port 8080 and stores state only under /config. Compose maps a named volume to /config and defaults to loopback access for safe initial setup. Health reports process liveness; readiness checks the database. Version is build-injected. JSON logs support DEBUG/INFO/WARN/ERROR and never log request bodies, cookies or query strings. Administrative setup/settings/server/library/job changes are audited. The OpenAPI document describes implemented routes only. The Plex worker shuts down with the process; its final cancellation is persisted before SQLite closes.

## Channel boundary (Phase 2)

`internal/channels` owns channel/group persistence, source validation, a parameterized rule compiler, deterministic membership resolution, metadata option queries and custom artwork storage. It imports no Plex service or HTTP response types. HTTP routes enforce session, role, Origin and CSRF boundaries, then call this service. React components under `web/src/channels` edit typed definitions and present paginated results; membership predicates and eligibility decisions remain server-side.

Migration 003 adds `channels`, `channel_groups`, `channel_sources`, `channel_static_items` and `channel_uploads`, plus safe audit target/summary columns and metadata lookup indexes. Sources are discriminated structured configurations in `channel_sources.config_json`. Static IDs/positions are normalized in `channel_static_items`; they are not duplicated in JSON. Rule version 1 is stored inside the source configuration, avoiding a redundant rule table. Existing metadata and show relationships remain authoritative. No schedule or program-entry tables are added.

`ResolveChannelMedia`, `CountResolvedMedia` and source previews share a compiler and centralized playable/eligibility predicates. Counts use SQL aggregation rather than loading result objects. Previews count and read one bounded page within a read transaction. Static order is explicit; show order is numeric season/episode; other sources use title/year/local ID with stable ties. Consumers receive normalized `channels.Media`, never raw Plex records. A later scheduler can consume these identities and durations but must introduce its own persistence, seeds, revisions and ordering policy.

The versioned rule AST has group nodes (`AND`, `OR`, one-child `NOT`) and condition nodes (`field`, `operator`, typed `value`). Field/operator allowlists map to fixed SQL fragments; all values use bound parameters. Depth, node, input-size and value-count limits bound work. References must exist in their correct domain. Collection references combine local entity ID and local library ID; labels include server/library context. A metadata selection lookup retrieves saved labels directly, without fetching every actor or collection.

Reference/enum operators are `is`, `is_not`, `in`, `not_in`. Strings support equals/not-equals, contains/not-contains, starts/ends-with. Numbers support equals/not-equals, greater/less comparisons (including equality), and inclusive between. Dates support before/after/between/within-last-days; dates normalize to UTC, and the relative-date clock is injectable. Availability supports is-true/is-false. Fields: library, server, media_type, title, show, season, genre, year, actor, director, writer, studio, collection, label, content_rating, rating, audience_rating, added_at, originally_available_at, duration and availability. `GET /channel-rules/fields` supplies the UI contract. Literal LIKE metacharacters are escaped. Positive NULL comparisons resolve false; negative conditions and NOT complement those results.

Genre/person/label/collection matching includes metadata attached to an episode's parent show, preserving normalized Plex hierarchy without duplicating relationships. Membership uses indexed item/metadata lookups. A correlated OR initially caused broad metadata scans; an indexed IN lookup over the item and its parent show reduced measured previews from seconds to tens of milliseconds.

Channel changes and their audit records commit together. Deletion never deletes Plex inventory. Uploads are content-addressed, fully decoded and bounded before storage, atomically renamed, and never accept user-supplied paths. Uploads and channel artwork are authenticated admin endpoints. The HTTP adapter may ask the existing Plex artwork service for a chosen media image; resolution itself has no network dependency. Artwork failure falls back to an escaped generated SVG; clients never receive a Plex token.

## Linear scheduling domain (Phase 3)

`internal/channels.ScheduleSnapshot` resolves one bounded normalized membership snapshot using the existing rule compiler and source ordering. It returns application IDs, durations and show/season identity. `internal/scheduler.Membership` is the dependency boundary; the scheduler imports no Plex client/service and performs no HTTP. The Phase 2 rule engine is unchanged.

`generator.go` is a pure, cancellable policy engine; `service.go` owns settings, fingerprints and transactional generation/repair; `queries.go` owns half-open current/next/previous lookup, paginated reads and integrity diagnostics; `jobs.go` is the bounded durable worker. HTTP owns RBAC/CSRF/Origin and serialization; React owns only forms, day selection, focus and preview presentation. `web/src/scheduler/api.ts` centralizes typed transport and display-time helpers.

Migration 004 adds `channel_schedule_settings`, `channel_programs`, `scheduler_state`, and `channel_schedule_history`; extends jobs with channel/actor, replacement count and affected range; and prevents duplicate active channel jobs. Channel deletes cascade schedules. Media references are protected by foreign keys. Unique channel/start and channel/sequence constraints, positive durations, exact end=start+duration checks and interval diagnostics guard integrity. Existing migration checksums remain unchanged. Channel create/duplicate writes settings in the channel transaction.

Schedule timestamps, anchor, coverage and affected ranges use UTC Unix milliseconds; foundation/job/audit timestamps retain seconds. Date-only browsing resolves midnight to the next calendar midnight in the channel timezone. Horizons use calendar-day arithmetic; repeat windows use elapsed 24-hour days. Stored absolute intervals remain continuous across DST and midnight. Rendering does not recalculate broadcast positions.

Fingerprinting hashes stable JSON of channel ID, relevant source config, mode/seed/anchor/repeat settings and normalized membership (ID, duration, type, show/season). Sequential preserves resolver ordering. Random modes canonicalize membership by ID so cosmetic ordering changes do not invalidate the timeline. Timezone/horizon changes alter coverage/display, not selection. Titles/artwork are joined at read time and not copied into fingerprints. Sequential title-based resolver order can legitimately change when a title changes.

The persisted sequence number continues selection across extension. RANDOM uses a seeded hash permutation repeated in complete cycles. SMART_RANDOM uses persisted scheduled air starts, choosing outside-window before relaxed-window, oldest first, non-immediate before immediate; deterministic show/season tie preferences and seed/position hash break ties. The last air start of each pruned media item is retained, so repeat windows longer than retained guide history remain effective after restart. This is scheduled history, not playback history.

Repair detects future duration/member/gap/overlap problems and replaces only the suffix from the first affected entry. Added membership, changed settings/source or sequential ordering invalidate the future suffix after the protected current entry. Explicit regeneration replaces all future rows. Already-started rows remain historical even if media changes or becomes unavailable. The retained prefix's exact end is the new segment origin. New programs, state/checkpoints, pruning, audit and job success commit atomically. Failure/cancellation leaves the prior timeline untouched. Diagnostics report historical corruption without rewriting it.

Plex and scheduler workers partition shared jobs by `PLEX_%` / `SCHEDULE_%`. A partial unique index bounds each channel to one active scheduler job; a single scheduler worker bounds CPU/writes. It runs maintenance every five minutes, processes queued work every two seconds, and uses a cancellation-aware shutdown. RUNNING jobs interrupted by restart are cancelled; the next maintenance enqueues fresh atomic work. Queue progress is deliberately indeterminate until commit. One SQLite connection remains a Phase 0 architectural tradeoff: reads can briefly wait behind generation. The real 1,320-member benchmark is recorded in VALIDATION.md.

Future blocks/slots/seasonal policies can become additional policy implementations around this normalized domain, with explicit wall-clock/DST rules. Playback will consume the existing current/next/previous API and local media IDs; no Plex playback transport or offset calculation exists in Phase 3.
# Phase 3.1 / Phase 4 boundaries

Migration 005 adds optional recency weighting and distinct-show cooldown columns. Recently Added is a typed `source.recent` template on ordinary RULE channels, not a permanent channel number or a second resolver. Server-side canonicalization enforces media type, availability and a relative UTC added-time window. The existing parameterized SQLite compiler still performs membership resolution. Default-off scheduler fields and omitted `addedAt` retain Phase 3 fingerprints byte-for-byte for existing channels. Recency participates in fingerprints only when enabled; relevant metadata or membership changes repair the future suffix using the existing protected cut point.

Distribution compares repeat eligibility, distinct-show cooldown, unseen/oldest air history, added UTC day, then deterministic seed/sequence/identity tie-breaks. It reconstructs show history from persisted/pruned air-start records. Constraints relax rather than deadlock; show separation is a soft preference subordinate to repeat eligibility. Historical programs and currently airing programs remain protected.

`internal/playback` consumes the scheduler's persisted current/next queries and application channel identities. It owns offset clamping, session ownership, playback mode, heartbeat interpretation and cleanup. It does not select a different program or generate schedules while tuning. `internal/plex/playback.go` owns live identity/version verification, capability checks, the Plex media-decision/start/stop protocol and HLS rewriting. Live metadata validates that the stored rating key/GUID still identifies the expected item. Synchronized inventory remains authoritative for local availability; a failed playback request never alters it.

Migration 006 adds `viewing_sessions`, with user/channel/program/media/server references, a hashed authentication-session association, state/offset/position, client identity, delivery mode and timestamps. No Plex token, upstream stream URL, local media path or decryption key is stored in playback responses or session rows. Random application session IDs identify bounded in-memory proxy descriptors; every request additionally requires the owning authenticated user. Logout stops only sessions associated with that login. Restart invalidates descriptors and stops persisted application sessions. Upstream cleanup failure is logged safely and Plex's timeout remains the final fallback.

Direct Play forwards byte ranges from verified Plex Part keys; multipart sources are rejected for now. HLS first calls `/video/:/transcode/universal/decision` using the same session/client identity as `/start.m3u8`. Plex requires this decision for some items. Manifests are bounded, parsed for URI lines/attributes, and rewritten to opaque application resource IDs. Only relative paths inside that exact Plex transcode-session namespace are registered. Unknown resources, external URLs, traversal, redirects and multi-range requests are rejected. Tokens remain in upstream request headers. Responses forward only media content headers; upstream errors/bodies are not exposed. Stream contexts cancel on stop and per-write deadlines bound stalled downstream clients without imposing a whole-movie timeout.

The frontend's `playback/controller.ts` owns browser transport, HLS.js, stale-response rejection, initial seek, heartbeat and server-directed boundary transitions. React renders the player and controls. The player is lazy-loaded and replaces the shell, avoiding focus-handler conflicts. Server time/offset is authoritative; a ten-second drift tolerance avoids incessant seeks. HLS manifests use full media coordinates, allowing beginning/live/normal seeking. Behind-live viewers do not jump to a different program automatically; Go Live explicitly rejoins current programming. Numeric entry and channel surfing use the same ordered enabled/visible catalog. No full EPG or mini-guide is included.

Protocol references: [Plex Media Server API](https://developer.plex.tv/pms/) and [Plex Direct Play/Direct Stream](https://support.plex.tv/articles/200250387-streaming-media-direct-play-and-direct-stream/). Actual protocol behavior is additionally exercised against a mock server and the operator's configured server; validation evidence is in VALIDATION.md.

## Phase 5 guide and viewer preferences

`internal/guide` is a local SQLite read domain. It batches channel/group/favorite metadata and joins program/media/show data for a bounded window using half-open intersection (`end > start`, `start < end`). On Now ranks indexed persisted programs once per channel before joining metadata for at most current/next. Details add normalized genres (including show inheritance). No Plex transport is imported. Guide classification and progress use one server clock sample; media/stream resolution remains solely playback's responsibility.

Migration 007 adds `user_channel_favorites`, `viewer_preferences` with a channel foreign key, a global time-window index and `viewing_sessions.origin`. Typed preferences coexist with the original generic preference table without overwriting it. HTTP routes use the authenticated user identity, never a client-supplied user ID. Enabled/visible channel checks apply to details, favorite creation, historical tuning and artwork. Removal of a favorite is idempotent even if its channel has since been disabled.

Playback accepts an optional retained program ID only with FROM_BEGINNING, scoped to the requested enabled/visible channel. It rejects future/unavailable entries, resolves the existing Plex adapter, starts at zero and persists origin LIVE/CURRENT_FROM_BEGINNING/CATCH_UP. Historical catch-up never promotes itself to LIVE or transitions automatically at the old broadcast boundary. Go Live performs fresh authoritative current-program resolution. Successful tune updates the user's last-channel foreign key. No schedule rows are changed by viewing.

`web/src/guide` separates typed transport, timeline/calendar utilities, grid cells/header, details, modal focus, favorites and mini-guide. Timeline geometry is a single six-pixels-per-minute mapping, clipped to each three-hour query. Calendar navigation resolves IANA-zone midnights and tests 23/25-hour days; display uses application timezone and 12-hour English times. Row virtualization retains the selected row; channel pagination bounds data even with large installations. Epoch checks prevent stale window responses from overwriting newer navigation. The server-time sample plus a monotonic browser clock drives progress independently of the 30-second metadata refresh.

Guide memory retains time/channel/filter/scroll selection within the authenticated user identity. Modal focus traps and Escape handling take precedence over shell/player keys. Favorite mutations restore a remaining cell, or NOW when the filtered list becomes empty. The fullscreen player keeps its controller mounted while guide/details/mini-guide overlays browse; only explicit tuning invokes session replacement. HTTP-LAN clients use `crypto.getRandomValues` for random client identities instead of secure-context-only `randomUUID`.

## Phase 6 — broadcast presentation

Baseline a99048d inspected and tests/builds passed. A stopped-container /config snapshot and Phase 5 image are preserved privately. Migration 008 adds normalized assets/tags/rules, channel defaults/overrides, persisted presentation entries/history, branding and replaceable stream identifiers. `broadcast_timeline` is a union view over existing main programs and presentation entries. Presentation rows reference their following program; main program IDs and guide/history foreign keys remain intact. UTC millisecond half-open intervals remain authoritative.

`internal/interstitials` owns assets, validation, inheritance, eligibility and pure deterministic selection. The scheduler consumes an immutable snapshot with relevant rule/asset fingerprinting, inserts exact-duration breaks and main programs in one transaction, and reads persisted/pruned asset history for repeat avoidance. Seed, feature sequence and rule/asset identities break ties. Outside-window assets win; oldest/unseen assets provide finite-pool relaxation. Trailer relevance favors the following movie without bypassing repeat-window eligibility. Tags, inclusive local calendar dates, frequency and maximum clip duration constrain candidates. One break is bounded to ten minutes. No matching asset means no inserted time. Hourly rules mean first safe feature boundary after an hour crossing, including DST offsets; no feature is interrupted for a hard clock.

Repair preserves historical/current entries and, while a presentation is airing, its following main program. It rebuilds only from the existing safe future cut. Duration and asset/rule changes affect fingerprints; cosmetic names, logos, corners and opacity do not. Unrelated asset kinds/tags do not invalidate a channel. Retention saves last-air history before cascading old presentation rows. Referenced-asset deletion is refused, including retained historical references. Missing local files become unavailable for future selection and may recover when restored; Plex outages do not mark media inventory missing.

Playback resolves the union timeline into Plex program, Plex extra/media, local MP4 or metadata presentation. Stable `viewing_sessions.id` survives every live boundary; `timeline_entry_id` records the exact entry and `stream_session_id` isolates replaceable sources and HLS resource maps. Advance is serialized per viewer. Old resources are closed, stale URLs cannot access the replacement, and restart marks stale sessions stopped. End-of-video pause events cannot accidentally suppress live transition. Catch-up/from-beginning continues to target main program IDs without attached interstitials.

Optional failures show an explicit next-up card for the remaining persisted interval, then advance normally. This preserves advertised feature starts instead of silently advancing them. Confirmed missing extras are unavailable for future repair; transient Plex errors are not treated as deleted inventory. Local previews and playback support bounded single byte ranges. Files use random server-generated names and restrictive permissions under `/config/presentation`; uploads have extension/signature/codec/size/duration checks, two concurrent inspections, a 20-second ffprobe deadline, bounded output and no network protocols. No shell command executes user text. The runtime includes FFmpeg tools only for inspection, not an application transcoding pipeline.

Guide queries retain main program rows and original durations, so breaks are genuine time between cells rather than micro-cell spam. Scheduling Studio queries every timeline entry. Mini-guide emphasizes the next meaningful feature during a break; player/Home station-break state uses presentation identity. Mini-guide and Starting Soon aggregate paginated channel responses with a non-progress guard instead of silently stopping at 100.

Broadcast administration provides typed forms, file/drop upload progress, local previews, trailer discovery, rule editing, channel overrides and non-mutating branding preview. Live overlays use safe margins, subtle bug opacity and controls-aware hiding. Next-up is restricted to synchronized live viewing. No Phase 7 implementation is included.
